# G-OpenSteamTool v0.11.0

`IPCMessages.steamd` 内置进应用了。ipc 通道现在和 pattern 一样零输入：不需要选文件、不需要仓库，Steam 更新后点一次「全部生成」三条一起出来。

## 新增

- **内置上游 IDL**：`resources/ipc/IPCMessages.steamd`（4.3 KB，OpenSteamTool 上游原文，GPL-3.0）用 `include_str!` 编译进 EXE，`scripts`/`tools` 目录在运行时不再需要。
- **ipc 变零输入**：首次打开应用直接点「生成」，不再弹文件选择器。
- **可选覆盖**：设置页的「IPC 定义文件」默认为「内置（随应用分发）」；指定了更新的文件就走覆盖，按钮旁多一个「恢复内置」。
- **授权说明**：新增 `resources/ipc/NOTICE.md`，注明该文件来自上游、未修改、许可与已随包分发的 `OpenSteamTool.dll` 相同。

## 为什么可以内置

IDL 描述的是接口/方法/入参个数这类语义信息，只在 Valve 增删 IPC 方法时变化，属于「跟着上游走」的静态资产；而 `funcHash` / `fencepost` 仍然每次都从当前 `steamclient64.dll` 里现抠。所以内置一份默认、允许覆盖，既省掉用户输入，也不挡住将来上游更新。

## 验证

- 不传 IDL：`ipc/steamclient` 正常生成，内容与本机一直使用的那份 976 B 文件逐字节一致。
- `generate_all` 用例改为断言三条通道全部写出、`skipped` 为空。
- 传覆盖 IDL 与不传，两条路径都跑过。
