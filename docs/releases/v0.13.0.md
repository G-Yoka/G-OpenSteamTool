# G-OpenSteamTool v0.13.0

「本地自动获取」现在会把 DLC 一并带上。

## 新增

- **DLC 枚举**：从 `appcache/appinfo.vdf` 的 `appinfo.extended.listofdlc` 读出该 App 的全部 DLC AppId，不再只处理主内容。
- **DLC Depot 三源合并**：DLC 自身的 `appinfo` 条目、主 App 上带 `dlcappid` 的 Depot、以及 `appcache/packageinfo.vdf` 中已购包（`appids` → `depotids`）的内容 Depot，去重后按 Depot ID 排序。
- **本地 Key 合并**：每个 Depot 单独到 `config.vdf` 的 `depots` 映射取 `DecryptionKey`；`key_found` 表示该 DLC 已有本地内容，结果按「有 Key 优先」排序。
- **分组界面**：发现结果在「Depot 解密」区按「主内容 / DLC 1..n」两组显示，每个 DLC 带名称、AppId、`depot · key` 计数与「加入 / 已加入」开关；已有本地 Key 的 DLC 默认勾选。
- **写入规则**：加入某个 DLC 时先写该 DLC 的 `addappid(<DlcAppId>)` 拥有标记，再写内容 Depot（有 Key 即 `addappid(<depot>, 0, "<key>")`）与对应的 `setManifestid`。
- **命令行自检**：`cargo run --example dump_discovery -- "<Steam 目录>" <AppId>` 输出与界面同源的发现结果，便于没有 GUI 的环境排查。

## 变更

- 「本地自动获取」的提示语补充 DLC 统计：`N 个 Depot（M 个含本地 Key），K 个 DLC 中 J 个已有内容`。
- 换 AppId 会丢弃上一次的发现结果，避免把别的游戏的 DLC 写进当前配置。

## 下载通道（随包提供）

- 设置页新增「下载通道 manifest.lua」：写入 / 更新 / 移除 `<Steam>/config/lua/manifest.lua`，默认 ManifestDeX 取码链，可填自建端点。
- 「下载通道自检」按 Steam 的下载地区选 CDN：读 `config.vdf` 的 `CurrentCellID`，通过 `IContentServerDirectoryService/GetServersForSteamPipe` 取同区域 SteamCache，逐个尝试；都不可用时回退最近 `content_log.txt` 里的节点、再回退 provider 提示。
- 自检结果直接显示取码源状态、所用 CDN 与清单字节数。

## 边界

- 仍然不联网获取 Depot Key：Key 只来自本地 `config.vdf`，账号本地没有的 DLC 不会凭空出现。
- DLC 若既没有本地 `appinfo` 条目、账号也没有对应已购包记录，Depot 列表为空，面板显示「无 depot 数据」，需要手工补行。
- 分组只影响发现与写入的内容，`G-<AppId>.lua` 的格式与元数据行不变。
