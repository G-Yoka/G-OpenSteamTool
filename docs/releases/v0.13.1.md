# G-OpenSteamTool v0.13.1

修好了「安装成功、下载却提示无互联网连接」。

## 根因

OpenSteamTool DLL 读 `config/lua/*.lua` 不是整文件加载，而是**逐行累积、能编译就立刻执行并清空**
（`LuaConfig::ParseFile` 里的 `luaL_loadstring` 循环）。v0.12 / v0.13 生成的模板是这样：

```lua
local SOURCES = { ... }          -- 一个 chunk，执行完 local 就没了
local memo = {}                  -- 又一个 chunk
local function fetch(...) ... end -- 再一个
function fetch_manifest_code_ex(...)  -- 全局，但引用的全是已销毁的 local
```

于是每次取码都抛 `attempt to index a nil value (global 'memo')`，DLL 回落到
`[manifest] url`（`wudrm` 已经 502），Valve 返回 `Access Denied`，Steam 把失败显示成
「无互联网连接」。

## 修复

- `render_manifest_lua` 改为自包含模板：不再有顶层 `local`；取码源与缓存放在
  `GOST_MANIFEST_SOURCES` / `GOST_MANIFEST_MEMO` 两个全局表里，其余逻辑全部在
  `fetch_manifest_code_ex` 函数体内。
- 新增回归测试 `render_has_no_top_level_local`：生成结果出现行首 `local` 即失败。
- 文件仍是 UTF-8 无 BOM，首行仍是 `-- GOST-MANIFEST-LUA v1`，因此老机器点一次
  「写入 / 更新」就会被覆盖成新模板。

## 验证

- 用 Lua VM 复刻同一套逐行加载逻辑跑旧模板：`attempt to index a nil value (global 'memo')`；
  跑新模板：返回 ManifestDeX 的真实 request code（`MATCH`）。
- `cargo test`：lib 24、集成 38、patterns 5，全部通过。
- 实机：替换 `<Steam>/config/lua/manifest.lua` 并重启 Steam 后，`logs/content_log.txt`
  出现 `manifest request received 200 (OK)`，下载队列恢复。

## 升级

下载新的 `g-opensteamtool.exe` 覆盖旧文件 → 打开工具 → 设置页「下载通道 manifest.lua」
点「写入 / 更新」→ 完全退出并重启 Steam。

> `manifest.lua` 必须保持 UTF-8 无 BOM。带 BOM 时第一行无法编译，整份文件凑不成完整 chunk。
