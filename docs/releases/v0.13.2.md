# G-OpenSteamTool v0.13.2

修复「别人的机器、别人的游戏都能列出 DLC，只有这个 App 一个都没有」的问题。

## 现象

Escape Simulator 2（AppId 2879840）在商店里明明有两个 DLC（Apocalypse DLC、Soundtrack），本地也有 Lua 配置，但「本地自动获取」只显示：

> 该 App 在 appinfo.vdf 里没有 DLC 记录

换到确实拥有该 DLC 的机器上，结果一样是空的。

## 根因

v0.13.0 的 DLC 枚举只读一个字段：`appinfo.extended.listofdlc`。

Escape Simulator 2 的本地 `appinfo` 条目里 **没有这个字段**（`extended` 存在，但只带 `dlcforappid` 之类），而它的两个 DLC 条目本身是齐的，各自带 `common.parent = 2879840`、`common.type = "DLC"`。于是数据在文件里、索引字段却缺一行，功能就整块哑掉——与「是否拥有 DLC」无关。

## 修复

- 枚举改成双路：先取 `extended.listofdlc`，再扫整份 `appinfo.vdf`，把 `common.parent` 或 `extended.dlcforappid` 指向当前 App 的条目一并纳入，去重排序。
- DLC 的 Depot 仍按三源合并（DLC 自身条目、主 App 的 `dlcappid`、`packageinfo.vdf` 已购包），Key 仍只从本地 `config.vdf` 取；`key_found` 判定与排序不变。
- 空状态文案改为可操作提示：先在 Steam 打开该游戏的 DLC 商店页刷新 `appinfo.vdf`，再重新获取。
- 新增回归测试 `dlc_appids_falls_back_to_child_entries_when_listofdlc_is_missing`，用 2879840 的真实结构做夹具。

## 验证

- 实机：`cargo run --example dump_discovery -- "D:\1_launchers\steam" 2879840`
  → `dlc=1`，列出 `4575720 Escape Simulator 2: Apocalypse DLC`，含 2 个内容 Depot（`4575721`、`4575722`）；本机未购买，`key_found=false`。
- 回归：MONSTER HUNTER RISE（1446780）DLC 数从 64 变为 68（子条目补全），主内容 Depot/Key 不变；Tabletop Simulator（286160）仍为 58。
- `cargo test`：lib 25、集成 38、patterns 5，全部通过。
