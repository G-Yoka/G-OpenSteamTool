# G-OpenSteamTool v0.13.3

已保存的配置里，终于能一眼看出哪几行是主体、哪几行是 DLC。

## 现象

「本地自动获取」生成的 `G-2879840.lua` 里有三十多行 `addappid`：`2879841…2879849`、`3843070…3843089`、`4185228`、`4575721`、`4575722`。重新打开这份配置时，分组面板已经不在（它只属于当次发现结果），表格只剩一列列数字，完全分不出哪些属于主内容、哪些属于 Apocalypse DLC。

## 修复

- Depot 表新增**「归属」列**：每行标注 `主体` 或 `DLC`，DLC 行的悬浮提示给出对应 DLC AppId。
- 归属变化处插入**分组条**：`主内容`、`DLC · Escape Simulator 2: Apocalypse DLC`，长配置也能一眼扫到边界。
- 标注由新的只读命令 `depot_ownership` 提供：选中配置时静默读取本地 `appinfo.vdf` / `packageinfo.vdf`，只返回 `AppId → 主体/DLC` 映射，不写任何文件、不弹提示、不改变表格内容；查不到的行显示 `—`。
- 命令行同样可查：`cargo run --example dump_discovery -- "<Steam 目录>" 2879840 --ownership`。

## 验证

- 实机 2879840：`rows=36`，其中 `base=33`（AppId 本身 + 32 个主内容 Depot）、`dlc=3`（`4575720` + `4575721`、`4575722`，名称 `Escape Simulator 2: Apocalypse DLC`）。
- `cargo test`：lib 26、集成 38、patterns 5，全部通过（新增 `ownership_rows_split_base_and_dlc`）。
- `npx tsc --noEmit`：通过。
