# G-OpenSteamTool v0.13.4

「自动获取时有 Key，进表格就没了」——两件事：看错了行，以及真会丢 Key。

## 先分清两行

一个 DLC 在条目表里占 **两行以上**：

```text
DLC · Escape Simulator 2: Apocalypse DLC          1/2 含 Key
DLC   4575720                                      内容拥有标记行，本身不带 Key
DLC   4575721  0  efe4af76…def822                  内容 Depot 行，Key 在这里
DLC   4575722                                      另一个内容 Depot，本机没有 Key
```

「1 个含本地 Key」指的是 `4575721` 这一行，不是 `4575720`。本版在分组条上直接标出 `1/2 含 Key`，并把 DLC 与它的 Depot 行放在同一分组下，避免再看错行。

## 真问题：重新获取会覆盖已有 Key

旧逻辑里，`本地自动获取` 完全按发现结果重建条目表，而发现结果只包含**当前机器 `config.vdf` 里存在的 Key**。于是：

- 从别人的 Lua 导入的 Key、手工填的 Key，只要本机 `config.vdf` 没有；
- 再点一次「本地自动获取」，这些 Key 就被清空，Manifest 也一起丢。

这正好解释了「获取时看到 1 个 Key，导入/重开之后看不到」。

本版改为按 AppId 合并：

- 发现结果有 Key → 用发现的；
- 发现结果没有、当前配置行上有 → **保留原值**；
- 解锁标记与 `setManifestid` 同样只补空、不覆盖。
- DLC 默认勾选条件增加「这份配置里本来就有该 DLC 或其 Depot 的行」，导入来的 DLC 不会再被默认取消。

## 验证

- 本机实测配置 `G-2879840.lua`：解析后 `4575721` 行保留 `efe4af76…def822`，`4575722` / `4575720` 保持空 Key。
- 重新获取（本机 `config.vdf` 无该 DLC Key）后，表格与保存结果均保留原 Key，不再清空。
- `cargo test`：lib 26、集成 38、patterns 5，全部通过；`npx tsc --noEmit` 通过。
