# G-OpenSteamTool v0.8.0

v0.8.0 把 pattern 通道的生成搬进了应用：Steam 更新后不再需要装 Python、不需要留一份仓库，点一下就能为当前构建生成数据文件。

## 新增

- **应用内生成 pattern 通道**：「数据通道」页每行多一个「生成」按钮，直接读取 `steamui.dll` / `steamclient64.dll`，在应用内完成 hook 解析 + 签名合成，并按当前构建的 SHA-256 写入 `opensteamtool/pattern/<component>/`。
- 通道页侧栏在缺文件时给出「生成缺失通道」，一步补齐；不再只能从本地挑 TOML。
- 生成结果与 `tools/pattern-tracker` 的 Python 流水线**逐字节一致**（除文件头注释行），可以直接互换。

## 实现

- 把 `pe.py` / `sig.py` / `resolve.py` / `rtti.py` / `tomlio.py` 移植为 Rust（`app/src-tauri/src/services/patterns/`），纯标准库 + 已有依赖，无新增运行时依赖。
- 规则集（`rules/steamui.toml`、`rules/steamclient.toml`）在编译期内嵌进 EXE，运行时不需要 `tools/` 目录。
- 生成在后台线程执行（`spawn_blocking`），界面不阻塞；实测 20 MB 的 `steamui.dll` 与 26 MB 的 `steamclient64.dll` 都在数秒内完成。
- 写入采用临时文件 + 替换，保留原有回滚语义。

## 仍未自动化

- **ipc 通道**需要上游 `IPCMessages.steamd`（接口 / 方法 IDL），不在本仓库也不随 EXE 分发，应用内点击会明确提示；这条仍走 `tools/pattern-tracker` 的 `ipc` 子命令。
- `layout` 偏移编译在 `OpenSteamTool.dll` 内，Steam 改变结构布局时仍需要上游重新出 DLL。
