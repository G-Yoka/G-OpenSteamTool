# G-OpenSteamTool v0.9.0

v0.9.0 把 ipc 通道也接进应用：pattern 与 ipc 三条通道现在都能在「数据通道」页一键生成，Steam 更新后不再需要 Python。ipc 比 pattern 多一个外部输入——上游的 `IPCMessages.steamd`，选一次记在本机。

## 新增

- **应用内生成 ipc 通道**：读取 `steamclient64.dll` 里每个 wrapper 的两条立即数（`funcHash` / `fencepost`），接口号与参数个数取自 IDL，输出与上游流水线一致。
- **恢复缺失通道**：通道页侧栏在缺文件时给出「生成缺失通道」，pattern 与 ipc 都会走应用内生成。
- **设置页新增「IPC 定义文件」**：记录 `IPCMessages.steamd` 路径（只存本机，不写入 `opensteamtool.toml`），可随时更换。
- 首次对 ipc 行点「生成」时自动弹出文件选择器，选中后记住路径，后续一键完成。

## 为什么 ipc 需要额外文件

ipc 每个方法要 5 个字段：`funcHash`、`fencepost`、`wrapper_rva` 可以从 DLL 里抠，但**方法清单、`interface_id`、`argc` 只存在于上游 IDL**。没有它，连「该找哪些方法」都不知道，`argc` 写错会让 DLL 按错误的参数个数解包回包——是静默失效，不是报错。

`IPCMessages.steamd` 来自 OpenSteamTool 上游源码（`src/Steam/IPCMessages.steamd`），不随本应用分发。没有它时 pattern 通道照常可用，ipc 会给出明确提示。

## 验证

- 与上游 `tools/pattern-tracker` 的 Python 流水线逐字节一致（除文件头注释行），pattern 两条与 ipc 一条都参与比对。
- 用真实构建实测：`steamui.dll`、`steamclient64.dll` + 本机 `IPCMessages.steamd` 生成的文件，与 loader 已接受的文件完全相同。
