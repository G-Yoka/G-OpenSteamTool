# G-OpenSteamTool v0.9.1

修一个会让配置关不掉的 bug：禁用一个配置后，磁盘上会同时留下 `G-<AppId>.lua` 和 `G-<AppId>.lua.disabled`。

## 修复

- **一个 AppId 只允许一份 Lua 文件**：写入配置时同时删除对侧文件，不再出现两份并存。
- **切换启停会自愈**：目标文件已存在时不再报「目标 Lua 文件已存在」，而是收敛到用户要求的状态并丢掉重复文件。
- **删除会清干净**：两种状态的文件都会移除，不再遇到第一个就提前返回。
- **编辑器开关直接生效**：右上角的启用/禁用不再只是草稿状态（之前点了会被同步逻辑立刻弹回），现在点一下就会改文件名并刷新列表。
- **编辑器状态同步**：切换启停后编辑器里的 `enabled` 跟随磁盘刷新，避免先禁用再保存时把启用副本又写回去。

## 成因

禁用走的是重命名（`G-xxx.lua` → `G-xxx.lua.disabled`），但编辑器表单里的 `enabled` 仍是旧值；此后再点保存就按 `enabled=true` 写出新的 `G-xxx.lua`，于是两份并存。旧实现里两条路径都不知道对侧文件的存在。

## 升级提示

已出现两份并存的配置，在 v0.9.1 里点一次「切换状态」或「保存」即可自动收敛。
